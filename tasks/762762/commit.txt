QThreadStorage: fix use-after-free on setLocalData() re-entrancy

A (direct or indirect) setLocalData() (of any type) could cause the
tls QList to be resized (see the top few lines of set()). If this
happens from the destructor invocation, the function's value reference
dangles afterwards.

To fix, re-seat the reference. Since references cannot be re-seated in
C++, and std::reference_wrapper isn't transparent enough (only reads
are transparent; assignments, esp. converting ones, like the one from
nullptr, need an explicit get()), change value to *ptr.

Bugs found by Claude, during an un-asked-for /code-review skill
invocation when asking Fable to review my fix of QTBUG-135044. Several
Opus passes over my patches before hadn't mentioned it. Reproducer by
Sonnet, with a -Wmarc pass afterwards. Fix in QtCore by yours truly.
