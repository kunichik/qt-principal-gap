[PS3 Reviewer 02 /COMMIT_MSG:37]
Depends on errno...

EWOULDBLOCK (EACCES/EAGAIN for the Android fcntl path) means a live process holds the lock. ENOLCK/EOPNOTSUPP/EINVAL/ENOSYS mean the filesystem can't do locks at all so the failure tell us nothing.

You handle the first kind now, but for the second kind "not stale" is wrong: on a no-lock filesystem stale locks become permanently unremovable (silently — same symptom as this bug). Since we already treat "no native locks" as success on platforms compiled without flock, the runtime case should degrade the same way: proceed with removal, trusting the staleness heuristics. In tryLock_sys() the missing handling is the other case: EWOULDBLOCK on a file we just created with O_EXCL means a stale-lock thief grabbed our fresh file so instead of proceeding without protection, close and return LockFailedError to go around the retry loop. For unknown errnos, default to treating it as held: when in doubt, don't delete.

[PS3 Reviewer 02 /COMMIT_MSG:37]
Claude says it can be fixed in tryLock_sys() with two small fixes:

* First, if setNativeLocks() fails with EWOULDBLOCK on the file we just created, a stale-lock remover flocked it before us: close and return LockFailedError instead of  warning and proceeding.

* Second, after locking and writing our data, verify we still own the name: fstat(fd) vs stat(fileName), compare st_dev/st_ino. If they differ or the file is gone, our file was removed or replaced while we were acquiring: close and return LockFailedError, and the retry loop starts over.

Between the two, the suspended locker can't return success on a deleted file: either the remover flocked first (check 1), or it flocked, unlinked and closed before our flock — and then the stat comparison catches it (check 2). Once we hold the flock and have verified, removal requires taking the flock, which fails. On filesystems where locks don't work at all this can't be made airtight, but that's the pre-existing degraded mode.

(unrelated to EBUSY/NFS, so probably for a separate commit)
